provider-adapter (`PhoneAuthProvider` interface, `mock` / `supabase` /
disabled implementations selected once at module load by
`EXPO_PUBLIC_PHONE_AUTH_MODE`, screens only ever call `phoneAuth.*`). **Use
this exact shape for every integration below** — it is not a proposal, it is
the template already validated by `tests/authPhone.test.mjs`/`phoneOtp.test.mjs`.

## Mock plan constraints (already satisfied by the phone-auth precedent, must hold for every future adapter)

- Never create a fake production authentication session — `mock.ts`'s
  `verifyOtp` explicitly returns `'verified-mock'`, a status distinct from
  `'authenticated'`, and the screen's copy states plainly that mock mode
  passed a UX flow, not identity.
- Never bypass Supabase RLS/authorization in production — the disabled
  provider (`createDisabledPhoneAuthProvider`) fails closed by design, and
  the mode resolver explicitly rejects a release build requesting mock mode
  (`resolvePhoneAuthMode`'s `configError` path).
- Never claim verification, protection, or payment that did not occur — this
  is the same rule the atlas states for money language, extended to every
  other trust surface.
- Every dev/sandbox surface must be **visibly labeled** in the UI, not just
  documented — `VerifyPhoneScreen`'s "MOCK MODE" / "DEVELOPMENT CODE" banner
  is the reference implementation for this rule; a future payment sandbox
  screen should carry an equally explicit on-screen label, not a code
  comment only.
