## How to talk to the operator (their words, today)

- **Summarize any plan in the most concise way. Basic terms, plain English. Do not say
  more than what needs to be said.** Short bullets. Lead with what they will SEE.
- Ask the important questions FIRST (`AskUserQuestion`, a "(Recommended)" first option);
  they answer fast and sometimes type free text into the answer — read it.
- **Options before code.** They pick from rendered PNGs (a NOW row + a–f, each varying
  ONE thing), then the pick is baked into a tracked reference HTML, then the run makes the
  app match it — by measurement, not by eye. "Show me what fixed looks like first in HTML,
  then use it as the reference to make it accurate."
- Renders must be honest: nothing the phone cannot draw; the label inside each frame;
  NOW beside each option when sizes differ (they could not see 6pt steps in a shrunken
  composite); verify structure before sending (no nested phones, equal tile widths).
- They have ADHD and asked for speed. One question per round when possible. No essays.
- After each run: commit by path, push, publish the OTA (they said yes to auto-publish
  today; ask once per run), one push notification, then they walk the Beta twice-opened.
