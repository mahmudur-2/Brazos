2026-09-04 — night1 (n3): the 72-hour auto-release gates on TOLD, not PUSHED, with a 7-day fallback. DECIDED: `auto_release_due_payments()` releases a stripe row 72 hours after completion once a `job_completed` `notification_outbox` row exists for the customer in ANY terminal status (`sent`, `skipped`, `failed`) — the in-app feed shows the row whether or not a push left the server, so the row's existence is what "told" means; a pending row still refuses — and unconditionally 7 days after completion, both under the same refusal set as `release_job_payment()` (open issue report, card dispute, refund-directed or parked, held). Reason: the old gate (`status = 'sent'`) conflated "the customer knows" with "a push left the server" — a customer without push permission, with Job updates off, or who muted or blocked the worker could hold a completed, undisputed job's payment for ever, and the worker bore the cost (`docs/BACKLOG.md` §v1 bugs, the auto-release liveness item). WITHDRAWN: the R12 plan to gate the money timer on DELIVERED (`docs/BRAZOS_TARGET_ARCHITECTURE_v3.md` §4.1 row 8, "the money timers wait for *delivered*, not `sent`") — delivery truth is a push concern, not a money gate; R12's receipt polling and dead-token retirement stand, its money-timer clause does not. THE CATEGORY: `job_completed` moves from the user-toggleable `job_updates` to the always-on `jobs` category, and `should_notify()` returns true for `jobs` before the block and mute checks (after the null-recipient, self-actor and inactive-recipient refusals), so a preference, a mute or a block never suppresses it. The always-on category already existed (phase75, `when 'jobs' then true`), so the plan's continue-path for a missing category did not apply; what it lacked was the block / mute bypass, which this supplies. Deliberate consequence: the existing `jobs` events — `dispute_opened` and `payment_released` — bypass block and mute too; both are money or dispute events between two parties already in a contract, which `tests/notificationFeed.test.mjs` already records as deliberate.
